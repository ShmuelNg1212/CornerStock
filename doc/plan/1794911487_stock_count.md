## OPEN QUESTIONS

4. A count covers the whole location (recommended for the first version)? Or a part of it (one brand or one shelf)?
5. Who finishes a count and applies the corrections? Recommended: all staff count and move balls between locations. Only the owner marks a missing ball as removed or puts a sold ball back in stock (same as today).
6. Keep a record of past counts (recommended: date, location, who, totals)? Or show only the result at the finish?

## Goal

Staff count one location by scanning each ball. The app shows missing and unexpected balls, and each correction takes one tap.

## Rules (to confirm, then record in an ADR)

- One open count for each location at a time. Staff on several phones add scans to the same count.
- A scan records the serial only once in a count. A second scan of the same serial adds nothing.
- The comparison runs at the finish, against the in-stock balls of the location at that time.
- Missing: in stock in this location, not scanned. Unexpected: scanned, but not in stock in this location (in a different location, sold, removed, or not recorded).
- A count changes no stock. Only a tap on a correction changes stock, through the existing database functions.

## Tasks

- [ ] **1. Count tables and functions.** `tests: first`
  - Migration: tables `counts` (location, started by, started at, finished by, finished at, status) and `count_scans` (count, serial, scanned by, scanned at; unique count and serial). Row-level security: staff read and write through functions only.
  - Functions: `start_count(location)` (returns the open count if one exists), `add_count_scan(count, serial)` (returns the ball status: found, other location with its name, sold, removed, not recorded), `finish_count(count)` (returns missing and unexpected lists, and closes the count), `cancel_count(count)`.
  - Acceptance (database tests): two starts for one location give one count. A double scan gives one row. Each scan status is right. The finish lists a missing ball and an unexpected ball. A ball sold during the count is not missing. A finished count refuses new scans. A signed-out user and an inactive account are refused.
  - Done when: `npm test` passes.

- [ ] **2. Serial-only capture.** `tests: first`
  - Add a count mode to the capture rule: the serial alone, confirmed in 2 frames of the window. The UPC is not needed. The intake rule does not change.
  - Acceptance: unit tests: serial in 2 frames captures in count mode and does not capture in intake mode; a different serial in the window stops the capture.
  - Done when: `npm test` passes.

- [ ] **3. Count screen.** `tests: first` for the state, `tests: alongside` for the screen.
  - Entry: "Count stock" on the stock screen, for the selected location.
  - The batch viewfinder in count mode. Each scan shows its status at once. A running total: scanned, expected.
  - A typed serial is also accepted (a damaged label).
  - "Finish" shows the result: found, missing, unexpected.
  - Acceptance: unit tests for the count state (add, duplicate, status). Browser probe with the fake camera: 2 labels scanned, the result lists the third recorded ball as missing.
  - Done when: tests and the probe pass.

- [ ] **4. Corrections from the result.** `tests: alongside`
  - Unexpected, in a different location: "Move here" (`transfer_ball`).
  - Missing: owner only, "Mark removed" with the reason "Not found in the stock count" (`remove_ball`).
  - Unexpected, sold: owner only, "Put back in stock" (`reverse_sale`), with a reason.
  - Not recorded: "Add" opens the normal confirm screen.
  - Each correction shows in the activity log with the count date in the reason.
  - Acceptance: probe: one move and one removal from the result; the activity log shows both.
  - Done when: the probe passes.

- [ ] **5. Count record.** `tests: alongside`. Only if question 6 says yes.
  - A list of past counts on the Activity screen or in Settings: date, location, who, totals. A row opens the result.
  - Acceptance: the probe sees the finished count in the list.
  - Done when: the probe passes.

- [ ] **6. Design pass.** `tests: alongside`

## Out of scope

- A count of a part of a location (question 4), unless the human selects it.
- Shoes, bags, accessories.
- Offline counting.
