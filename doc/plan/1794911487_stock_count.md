## Answers from the human (2026-11-17)

4. A count covers the whole location.
5. All staff count and move balls between locations. Only the owner marks a missing ball as removed or puts a sold ball back in stock.
6. Keep a record of past counts: date, location, who, totals. Task 5 is in scope.

## Goal

Staff count one location by scanning each ball. The app shows missing and unexpected balls, and each correction takes one tap.

## Rules (confirmed; record in an ADR in task 1)

- One open count for each location at a time. Staff on several phones add scans to the same count.
- A scan records the serial only once in a count. A second scan of the same serial adds nothing.
- The comparison runs at the finish, against the in-stock balls of the location at that time.
- Missing: in stock in this location, not scanned. Unexpected: scanned, but not in stock in this location (in a different location, sold, removed, or not recorded).
- A count changes no stock. Only a tap on a correction changes stock, through the existing database functions.

## Out of scope

- A count of a part of a location (answer 4).
- Shoes, bags, accessories.
- Offline counting.

## Deviations from the plan

- Task 1: a function `correct_count_line` makes each correction. It checks the line, builds the reason from the count date and location, and calls the existing stock function. The current stock decides the correction, not the kind at the finish. Thus a sold ball that goes back to a different location then offers "Move here".
- Task 1: a function `count_result` gives the kept result, with `corrected` and `action` for each line from the current stock. A function `count_history` gives the past counts.
- Task 1: a move from a count uses the internal function `transfer_ball_with_reason`. `transfer_ball` keeps its 3 arguments and gives no reason. Clients cannot set a move reason.
- Task 3: the count is on its own screen, `/count`. "Count stock" is on the stock screen, and "Stock counts" is on the Activity screen.
- Task 4: "Add" opens the normal scan. The serial is not filled in: the scan reads it from the label.
- Task 4: an unexpected ball recorded as removed has no correction from the count (ADR 0005, rule 6).
- Task 5: the list of past counts is on the count screen, below the start. The Activity screen links to it.
