# Plan: easier navigation and more motion ("The lane")

Status: draft, waits for approval. Mode: design. Branch: `feat/ui-flair`.
Study: [../study/1794842063_ui_flair.md](../study/1794842063_ui_flair.md).

## OPEN QUESTIONS

1. **Reference shot.** The agent cannot open the Dribbble shot. Dribbble blocks automated clients. Recommended: paste one or two screenshots of the shot into the chat. The agent then updates the direction before execute. Without them, the agent uses the common patterns in the study.
2. **New motion rule.** "More flair" changes ADR 0001. Proposed rule: "Motion has character, but each motion has a cause: a navigation, a state change, or a touch. Motion with no cause stays forbidden. Reduced motion stops all movement." Recommended: yes. Task 1 then writes ADR 0002 and updates AGENTS.md and PRODUCT.md.
3. **Motion library.** ADR 0001 says "no animation library". Row movement during a search, interruptible springs, drag to close a sheet, and swipe back need one. Recommended: add `motion` (`motion/react`), loaded with `LazyMotion` to keep the first download small. Alternative: CSS and view transitions only. Then rows do not move during a search, and sheets and swipes have no drag.
4. **Third tab for staff.** The new phone bar is: Stock, a large Scan button in the center, and one place on the right. The owner gets Settings there. Staff today have no third place. Recommended: staff get "Account" (name, location, sign-out). The owner's Settings also holds these.
5. **Swipe back on the phone.** Recommended: yes, from the left edge, on detail screens only. It does not conflict in the home-screen app. In Safari it can conflict with the browser's own back swipe; there the app's swipe turns off.
6. **Haptics.** The web vibration API works on Android only. iOS Safari has none. Recommended: a short vibration on Android when a barcode is found and when a ball is saved. Nothing on iOS.
7. **Release.** A push to `main` deploys. Recommended: the work stays on `feat/ui-flair` until you say "ship".

## Decisions already made

- Brand, palette, type, logo, light theme: no change (ADR 0001).
- "Find first" stays. The list and detail pane on large screens stay.
- No change to the database functions, the label rules, or the server actions' behaviour.
- No charts, no dashboard.

## Rules for each task

- Read the related guide in `node_modules/next/dist/docs/` before code that touches layouts, routes, or view transitions.
- Read impeccable's `reference/craft-floor.md` immediately before each UI edit.
- Each animated element has one owner: a view transition or `motion`, never both.
- Each animation: transform and opacity only; interruptible; stops under reduced motion.
- After each task: `npm run typecheck`, `npx eslint .`, `npm run test:unit`.
- Browser check on the preview route at 390px and 1440px, in Chromium and WebKit, with and without reduced motion.
- One Conventional Commit for each task.
