# Study: easier navigation and more motion ("flair")

Date: 2026-11-16. Mode: design. Branch: `feat/ui-flair`, made from `main` at `a044f49`.

## Request

The human asked for these changes:

- Make navigation easy and seamless.
- Give the app more flair in its motion.
- Keep the brand and the color scheme.
- Keep the main function first: bowling ball stock, the live stock view, and intake by a label scan.
- Use the Dribbble shot "Ai inventory app design" (`dribbble.com/shots/26804873`) as inspiration only.

## The reference shot

The agent could not see the shot. Dribbble returns an empty page to automated clients. A search found no copy or description of it. The agent did not try to get past Dribbble's block.

Thus this study does not claim anything about the shot. The plan asks the human for a screenshot (OPEN QUESTIONS, item 1). Until then, the direction uses the patterns that are common in current inventory app designs:

- A floating tab bar with a moving indicator.
- A short summary at the top of the home screen (counts as large numbers).
- Filter chips under the search.
- Large rounded cards with a bold number.
- A large, central scan action.
- Sheets that come up from the bottom.

Each pattern is a candidate only. The plan keeps a pattern only if it makes a task faster for shop staff.

## Current interface: findings

Source: the preview route with fixture data at 390px and 1440px. Screenshots: [assets/ui-flair/](assets/ui-flair/).

### Navigation

1. **Two scan controls on the phone.** The tab bar has "Scan", and a floating "Scan label" button sits above it. The floating button covers the weight chips of a row.
2. **The search scrolls away.** On the phone, the search field goes off screen after one model card. To search again, the staff member must scroll to the top.
3. **No weight filter.** The main counter question is "Do you have it in 15?". Today the staff member reads each card to find the 15 lb chips.
4. **No brand filter.** The list is one long scroll. There is no quick way to show only Storm, or only Hammer.
5. **The location name is cut.** The phone top bar shows "Sta. Luci…". The staff member cannot see which location is selected.
6. **The back control is small.** On the phone, "‹ Stock" is a small text link at the top left. It is far from the thumb.
7. **No path from a detail to the next detail.** On the model screen, other weights of the same model need a back step first.
8. **The tab bar is plain.** The current tab shows only by a light fill. A tab change has no motion.

### Motion today

- A detail screen slides in from the right on the phone. The detail pane fades on large screens.
- A changed count ticks up. A changed row gets a gold mark.
- The skeleton fades to the content.
- Buttons have a press scale.

What is missing:

- A model row does not move to its new place during a search. Rows appear and disappear in one frame. (Study `1794816127`, risk 3: CSS alone cannot keep row identity in a React list.)
- No shared element. The weight chip does not become the weight tag of the detail screen.
- The sheets open with the browser's default dialog behaviour.
- A save after a scan has no strong signal. The focal moment of the earlier plan is still not built.

## Constraint from the decisions

ADR [0001](../adr/0001-brand-kit-confirmed-and-functional-motion.md) says:

- Motion is functional and quick. It shows a state change. It does not decorate.
- No animation library is added.
- Under the reduced-motion setting, nothing moves.

"More flair" changes this intent. The agent proposes this reading:

> Motion has character, but each motion still has a cause: a navigation, a state change, or a response to a touch. Motion with no cause stays forbidden. Reduced motion still stops all movement.

This needs the human's approval and a new ADR (OPEN QUESTIONS, items 2 and 3).

## Direction: "The lane"

A bowling lane is a straight path with one goal at the end. Navigation follows the same idea: one clear path from search to ball, and the scan always at the thumb.

### Navigation changes

- **Phone tab bar becomes a floating bar** with three places: Stock, a large central Scan button, and Settings (owner) or Account (staff). The floating "Scan label" button is removed. A navy pill moves under the current tab.
- **The search stays on screen.** It sticks to the top when the list scrolls. The top bar gets smaller during the scroll.
- **Weight chips under the search**: "All", then each weight that is in stock, 10 lb to 16 lb. A tap filters the list to that weight. The chips show the count for each weight. The filter is in the URL (`?w=15`).
- **Brand filter**: a second chip row, or a sheet. The agent recommends a sheet that opens from a "Brand" chip, because the brand list can be long.
- **Location**: on the phone, the location becomes a chip in the stock summary ("77 balls in Sta. Lucia East ▾"). A tap opens a sheet with the locations. The top bar then has space for the full name.
- **Back by swipe and by a large control.** The phone detail screen gets a back button of 48px at the bottom left, in the floating bar's place. An edge swipe from the left also goes back.
- **Weight switcher on the model screen.** The model screen shows the other weights of the model as chips. A tap changes the weight in place.
- **Keyboard on the counter computer.** `/` focuses the search. `Esc` clears it. Arrow keys move through the rows. `Enter` opens the selected row.

### Motion changes

Each item has its cause.

| Moment | Cause | Motion |
|---|---|---|
| Tab change | navigation | The navy pill slides to the new tab with a spring. The icon makes a small press. |
| Search and filter | state change | Rows that stay move to their new place. Rows that go fade and shrink. New rows fade in with a short stagger (30 ms per row, 6 rows maximum). |
| Chip to detail | navigation | The weight chip morphs into the weight tag of the detail screen (shared element). |
| Detail open on the phone | navigation | The screen slides in from the right. A swipe can pull it back with the finger. |
| Sheet | state change | The sheet comes up with a spring. A drag down closes it. |
| Count change | state change | The digits roll to the new value (each digit moves up or down). |
| Scan: barcode found | state change | The corner brackets of the viewfinder close in on the label. A short haptic on phones that support it. |
| Scan: ball saved (focal moment) | state change | The label photo shrinks into the saved row. A ball icon rolls into the corner bracket of the Stock tab. The Stock tab count goes up by one. 600 ms maximum. |
| Live change | state change | The changed row gets the gold mark and a short gold sweep across the row, once. |
| Press | touch | Each control gives a spring press (scale 0.97). |
| Sign-in | navigation | The corner bracket of the logo closes around the ball, once, then the form fades in. |

Budget:

- Transform and opacity only. No blur. No layout properties.
- Routine motion: 150 to 250 ms. Sheets and screens: springs that settle in 350 ms or less. The focal moment: 600 ms maximum.
- An interrupted motion goes from its current place to the new target. It does not jump.
- Reduced motion: nothing moves. The colors, the gold mark, the count, and the toasts stay.

### What stays

- The palette, the type, the logo, the light theme.
- "Find first": the search leads the app.
- The list and the detail pane on large screens.
- The database functions, the label rules, and the server actions.
- The status badge with an icon and a label.

### What is not in this work

- Charts and a dashboard. They do not help staff find a ball. (Anti-goal of study `1794816127`.)
- A dark theme.
- New stock functions.

## Tools

- **Motion library.** Row movement during a search, springs that can be interrupted, the drag to close a sheet, and the swipe back need a layout animation tool. The agent recommends `motion` (`motion/react`) with `LazyMotion` and `domAnimation`, to keep the download small (approximately 15 KB gzip at first load, the rest loaded later). Its documentation is available through the `motion` MCP server.
- **View transitions** stay for the route changes and the shared element (chip to tag).
- **Skills:** `/impeccable animate`, `animate`, `motion`, `animation-performance`, `mobile-native`, `emil-design-eng`, `break-ui`, `review-animations` at rendezvous.

## Risks

1. A new library changes ADR 0001. It needs approval.
2. View transitions and motion layout animations can run on the same element at the same time. The plan gives each element one owner.
3. Safari support for view transition types is new. The phone checks must run in WebKit as well as Chromium.
4. A swipe back can conflict with the iOS system back gesture in Safari. In the installed home-screen app, iOS has no system back gesture. The plan tests both.
5. The screens behind sign-in are checked on the preview route with fixture data. A real scan and a real save need the human's device.
